## 主机回归

`python tools/test.py` 编译并执行五组 C 回归：核心规则、界面、战斗、存档和实际渲染。测试直接复用应用的游戏逻辑与 C 渲染器，导出 24 张 480×272 页面到 `build/screenshots/`。

- 核心包含 420 组定向楼梯传送；战斗包含 123 组怪物及强化组合。
- 存档覆盖六槽、旧档导入、取消、覆盖备份、短写、目录失败、主文件损坏回退、读取失败保留进度及保存退出。
- 界面覆盖相邻格触控、右侧功能、双列菜单、六槽选择、手册、传送、商店、对话及战斗跳过。
- 保留的 `input_edges` 测试针对旧 9588 辅助逻辑；H1 实际键盘循环通过下面的固件流程验证。

公开仓库的干净检出构建与五组回归在发布前另行执行；GitHub Actions 会从固定子模块重新构建，并检验连续两次 BDA 和安装 ZIP 是否逐字节一致。Actions 不运行私有固件，因此 CI 成功只代表构建、主机测试和产物校验通过。

## 完整固件模拟器

上述确切 BDA 在 H1 V1.41 完整固件与 H1 QEMU 中通过以下流程。测试使用专用 NAND 副本和独立端口，仅通过普通按键及触屏事件操作游戏；GDB 只读取状态，没有写入游戏 RAM。

- 从桌面游戏分类启动，显示标题与 8 页开场。
- 完成仙子 16 页对话，获得三种钥匙。
- 实体方向键及左右 ALT 矩阵键移动，地图相邻格触摸移动，触屏打开菜单。
- 创建 `A:\H1MOTA\`，保存第一槽；移动并开门消耗钥匙后读取，恢复位置、钥匙、属性及完整地图。
- 再次保存并退出，关闭游戏窗口并返回原生桌面。
- 停机后读回 `SLOT1.SAV` 与 `SLOT1.BAK`，均为 6,608 字节且校验有效。

## 限制与复核方式

尚未做物理 H1 真机验证，也未在完整固件中自动通关全部楼层。公开主机测试可以直接复跑；完整固件验证需要自行准备有权使用的 H1 V1.41 固件与匹配的 H1 QEMU 环境。固件验证使用了开发工作区的私有镜像部署适配器，该脚本不作为本仓库通用工具发布。

可用 SDK 的帧缓冲抓取及 GDB 读取工具复核运行画面和状态；应使用独立镜像，按上述顺序测试实体键、触摸、存取档与退出，并先核对 BDA SHA-256。模拟器验证不能替代物理设备验证。
